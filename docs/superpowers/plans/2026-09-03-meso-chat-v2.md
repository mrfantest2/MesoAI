# Meso Chat v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Memory-v1-backed `/meso/chat` page into a persistent conversation application with conversation navigation, safe rich rendering, regenerate/copy/stop controls, provider streaming with non-streaming fallback, and production-grade mobile/PWA behavior.

**Architecture:** Chat v2 consumes the verified Memory v1 API and keeps the server as transcript authority. Conversation navigation is a client layer over `conversations.php`/`messages.php`; rendering is DOM-based and never trusts raw HTML; generation supports a dedicated authenticated SSE endpoint while retaining the current JSON endpoint as fallback. Persona historical evidence and Conversation Memory remain separately labeled in every context path.

**Tech Stack:** PHP 8+, existing PDO SQLite Memory v1, vanilla JavaScript, Server-Sent Events over `fetch()`, Ollama `/api/chat` streaming NDJSON, OpenAI Responses streaming SSE, GitHub Actions, Windows MASTER-PC/XAMPP.

**Spec:** `docs/superpowers/specs/2026-09-02-meso-v3-memory-chat-voice-design.md`

## Global Constraints

- Memory v1 remains the sole persistent conversation store.
- Browser history is never authoritative.
- Persona v2 historical evidence remains isolated from Conversation Memory.
- Raw assistant HTML is never injected into the DOM.
- Streaming partial output is not persisted as a completed assistant message.
- Cancelled/failed streams do not create a normal final assistant message.
- Non-streaming `chat.php` remains available as a fallback.
- Production stays unchanged until exact-commit CI and MASTER-PC preflight pass.
- `/meso/api/*` remains network-only/no-store in the service worker.
- State-changing endpoints retain same-origin state authorization.

### Task 4: True streaming endpoint

**Files:**
- Create: `web/api/chat-stream.php`
- Extend: `web/includes/chat_runtime.php`
- Extend: `.github/workflows/meso-chat-v2-checks.yml`

**Interfaces:**
- Request: POST JSON `{conversation_id,message}`.
- Response: `Content-Type: text/event-stream; charset=utf-8`.
- Events are JSON payloads under SSE event names:
  - `meta` → conversation/persona/memory metadata
  - `delta` → `{text:"..."}`
  - `done` → `{message_id,provider,model,...}`
  - `error` → `{error,message?}`

- [ ] Add RED source tests for SSE headers, auth, no-store, bounded input, Memory/Persona context, and no raw provider payload passthrough.
- [ ] Implement `meso_chat_sse_event($event,$payload)` with output-buffer flushing.
- [ ] Ollama: call local `/api/chat` with `stream:true`, parse each NDJSON line, emit only assistant content deltas, capture final model metadata.
- [ ] OpenAI: call `/v1/responses` with `stream:true`, parse provider SSE lines, emit only text delta events (`response.output_text.delta`), and ignore unknown provider events.
- [ ] Persist user turn before provider work; accumulate bounded output; persist assistant only after normal provider completion and non-empty final output.
- [ ] On client disconnect/provider error, do not persist a completed assistant turn.
- [ ] Emit `done` only after assistant persistence succeeds.
- [ ] Run PHP syntax/static contract GREEN.
